# Known failures of the verified GC on the OCaml testsuite.
#
# The gate is "no NEW failures", not "zero failures": the collector implements
# neither weak pointers, ephemerons, finalisers, compaction nor memprof
# sampling, so a sizeable set of tests fails for reasons that are expected and
# understood. Gating on zero would be permanently red and stop being read.
#
# Regenerate: ci/testsuite_report.py --log LOG --expected THIS --update-expected
# Entries should only ever be REMOVED as fixes land, unless a note says why.
#
# Provenance, because a baseline is a claim about a specific collector: this
# list was measured on the reference branch, whose GC differs from this one by
# exactly one thing -- the allocator fix ("patch 17"), which makes a block
# declare the size that was requested rather than the size of the free block it
# came from. Everything else, including upstream's no-scan and infix work, is
# identical here; verified by diffing the extracted snapshot.
#
# EXPECT ONE NEW FAILURE on the first run:
#
#     tests/ast-invariants/'test.ml' with 1.1 (native)
#
# That is the allocator bug, not a broken pipeline. It parses every .ml file in
# the OCaml tree and segfaults once major-heap fragmentation makes the allocator
# hand back a block one word too large; the over-declared header then leaves a
# phantom field holding 0, which is not a representable OCaml value. Reproduce
# it directly with:
#
#     MIN_EXPANSION_WORDSIZE=8388608 ./test.opt <ocaml-tree-root>
#
# Do not baseline it. Fix it, then this file needs no change.
