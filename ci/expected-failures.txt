# Known failures of the verified GC on OCaml 4.14's own testsuite.
#
# CI fails only on a failure that is NOT listed here ("no new failures"). The
# collector does not implement everything the suite exercises, so a known set
# of tests fails for understood reasons; a zero-failure gate would be
# permanently red.
#
# Regenerate after a run (keeps this header):
#     python3 ci/testsuite_report.py --log testsuite.log \
#         --expected ci/expected-failures.txt --update-expected
# Entries should only be REMOVED as fixes land. Adding one needs a reason
# below.
#
# Why these fail:
#   - weak pointers, ephemerons, finalisers: not implemented (tests/misc/ephe*,
#     weak*, finaliser; ephe-c-api; tool-ocaml/t340-weak, t350-heapcheck; and
#     three whose names hide it: lib-sys/opaque, backtrace/callstack and
#     c-api/alloc_async all assert on Gc.finalise; regression/pr5233 reads a
#     weak entry after Gc.full_major has collected its value -- the verified
#     collector does not erase weak entries)
#   - weak arrays, ephemerons and Gc.finalise now fail early (issues #42, #43):
#     creating a weak array or ephemeron, or registering a finaliser, stops
#     with "Fatal error: ... not supported by the verified GC".  Tests that
#     used to pass while using one of them only incidentally now stop there:
#       misc/weaktest (Weak.Make), lib-bigarray/weak_bigarray (Weak.create),
#       basic/opt_variants (a Weak.Make set among other stdlib checks),
#       lib-hashtbl/htbl (Ephemeron.K1/K2.Make tables alongside Hashtbl),
#       backtrace/backtraces_and_finalizers (Gc.finalise; native only),
#       lib-marshal/intern_final (Gc.create_alarm, which uses Gc.finalise)
#   - Gc.Memprof sampling: not implemented (every tests/statmemprof entry,
#     including the timeouts)
#   - custom-block finalisers: not run (regression/pr3612)
#   - signal handlers are not run at allocation safe points: the verified
#     allocator does not consult young_limit (callback/signals_alloc,
#     lib-systhreads/eintr)
#   - Gc.set knobs the fixed-size verified heap cannot honour
#     (regression/pr9326 resizes the minor heap, which the verified runtime
#     ignores, and asserts that Gc.get reports the new size -- both variants;
#     regression/pr9292 asks for best-fit and ~400 MB, and gets Out_of_memory)
#   - packaging, not GC behaviour: no libasmrun_i.a (instrumented-runtime),
#     -output-complete-obj does not carry the verified GC's objects
#
# lib-systhreads/eintr's timing-sensitive variants are slow here: if one times
# out, the collector or the runner got slower -- investigate rather than
# baseline it.  (tests/misc/'weaktest.ml' carried the same warning until
# Weak.Make started failing early; see above.)
